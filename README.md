# GeeZip

**在 GEE 上先把数据压好，再下载。**

下遥感数据最花时间的一步，是把几十个波段原样搬回本地。而很多人下回来第一件事就是降维——
真正占带宽的那一步白走了。

GeeZip 把顺序倒过来：**编码器放云上，解码器留本地。**

```
   云端（GEE）              带宽              本地
 ┌──────────────┐                      ┌──────────────┐
 │ 特征栈 D 维   │                      │              │
 │      ↓       │   只传这一份 ↓        │  解码器还原   │
 │  编码器前向    │ ───────────────→     │      ↓       │
 │      ↓       │   k 波段 uint8       │  D 维反射率   │
 │ tanh → uint8 │                      │              │
 └──────────────┘                      └──────────────┘
```

---

## ★ 先说清楚：这是一个 skill，不是一个压缩模型

本项目是一个**给 AI 用的 skill（工作流）**，**不能直接拿我训练好的模型去压你的数据**。
例子里那份权重只对那一小块测试区有效——**你换了研究区，肯定要重新采样、重新训练、
重新搬权重、重新核对**。

但这些不用你操心：**有了这套工作流，AI 能全部自动完成。**

所以它**必须配合 AI 使用**（Claude Code 或 Codex）。单独 clone 下来当软件用，是用不起来的。

## 最简单的用法

**一、让 AI 装上它。** 打开 Claude Code 或 Codex，直接说：

> 安装 https://github.com/xulogin/GeeZip

**二、结合 skill 提需求。** 比如：

> 用 GeeZip 下载昆明 2023 年的 Landsat 影像，6 个波段

然后它会按仓库里写好的工作流，把取数 → 训练 → 搬权重 → 两道核对 → 下载 → 还原
一路做完，把结果和数值给你。

**你一条命令都不用敲。** 缺 Python 包它自己装，缺前置依赖 GeeLo 它自己拉，
GEE 没认证会弹浏览器让你点一下「允许」。

## 手动装（可选）

想自己装也行，两条命令：

```text
Claude Code:   /plugin marketplace add https://github.com/xulogin/GeeZip.git
               /plugin install geezip@geezip

Codex:         codex plugin marketplace add https://github.com/xulogin/GeeZip.git
               codex plugin add geezip@geezip
```

需要 Windows、一个 GEE 账号和 Cloud 项目，以及能正常访问 GitHub 和 Earth Engine 的网络。
（国内基本都要开代理——GeeZip 本来就要连 `earthengine.googleapis.com`，
代理是这套东西的前提，不是为装插件额外加的负担。）

## 实测

| 场景 | 输入 | 下载量 | 压缩比 | 还原误差 |
|---|---|---|---|---|
| landsat年度 | 6 波段 | 4.97 MB → **1.19 MB** | **4.2 倍** | 0.0043，**低于传感器自身噪声** |
| landsat季度 | 6 波段 × 4 季 = 24 维 | 19.73 MB → **2.44 MB** | **8.1 倍** | 0.0091 |

昆明 22 公里见方，Landsat 8/9，2023 年，30 米。

Landsat 自己的辐射定标精度约 0.005 反射率——**年度那组的压缩损失比卫星
本身的测量误差还小。**

**波段越多越划算。** 相邻季节的影像长得像，越像越有得压。这恰好是大范围
时序数据最头疼的场景。

## 它是怎么工作的

**编码器和解码器是一起训的**，一个负责把 D 个数压成 k 个，一个负责还原回去。
训练时就按下载要用的精度（uint8）取整，所以部署的和训练的是同一个模型——
不这么做的话，精度会在下载那一步无声无息掉一截。

**只有编码器搬上 GEE。** GEE 能做前向传播（算一遍），做不了反向传播（学），
所以训练留在本地。解码本来就发生在下载之后，留本地天经地义。

**搬完自动核对两遍**，都对得上才让你下载：

| 核对 | 看什么 | 看不了什么 |
|---|---|---|
| 一致性 | 同一组输入，本地和 GEE 算出来一不一样 | 输入本身对不对 |
| 特征指纹 | 两边的特征栈算出来一不一样 | 模型权重对不对 |

缺一不可。特征栈在 `场景/` 下的 `.py` 和 `.js` 里各写了一遍，
一旦两边漂了，第一道核对是抓不住的——脚本照样跑通、图照样出，数是错的。

实测两道分别对到 `1e-8` 和 `1e-11`。

## 换研究对象

跟 AI 说一声就行：换研究区、换传感器、换波段组合，它会带着你从头走一遍
采样 → 训练 → 核对。技术上就是改「场景」那一对文件（`.py` 和 `.js` 逐行对应），
引擎不用动。

## 几句实话

- **它是有损的。** 名字里有 Zip，但别当成 WinRAR。还原出来不是逐位复制。
  实测误差小于传感器自身噪声，对绝大多数应用够用；要做逐位精确的存档，别用它。
- **换个地方要重训。** 单期影像的波段关系比较普适，换地方基本不掉；
  但季相物候是地域性的，跨气候区实测误差会翻一倍多。要跨区用，训练时
  就得把多个区域混进去。让 AI 跑一次「外推」可以直接量出来。
- **它压的是波段之间的冗余**，不是图像空间上的冗余，和 JPEG 那类压缩不冲突。
- **小数据别用。** 就下一景几个波段，直接下更快，折腾这一套不划算。

## 一条踩出来的经验

**别用 `toArray` + `matrixMultiply` 去物化整幅栅格。**

逐点预测用它没问题，但整幅下载时会撞内存墙：

| | 全幅 743×743 @30m |
|---|---|
| 数组影像版 | `User memory limit exceeded` |
| **波段算术版** | **OK，1.19 MB，5 秒** |

MLP 的每个隐单元就是个加权和 `u_j = Σ W[j][i]·x_i + b_j`，用普通波段算术
表达即可。两版结果**逐位相同**（实测全幅最大差 = 0）。引擎里两版都在：
核对用数组版，下载用波段算术版，每次下载前自动对拍一次。

另外，编码器和解码器是 numpy 手写的，**不需要 PyTorch 或 TensorFlow**——
小到不值得上框架，通常几百到几千个参数。

## 姊妹项目

| | 管什么 |
|---|---|
| [GeeLo](https://github.com/xulogin/GeeLo) | 写和调普通 GEE 脚本。让 AI 连真服务器把脚本跑通、自己看报错、改完再交付 |
| [GeeDL](https://github.com/xulogin/GeeDL) | 在 GEE 上跑神经网络，输出预测值和逐像元不确定性 σ |
| **GeeZip** | 就是本项目。云上先压，只下压好的那份，回本地还原 |

三个都是 skill，用法一样：让 AI 装上，然后提需求。
GeeZip 的「搬模型 + 两道核对」方法来自 GeeDL，实跑测试台来自 GeeLo，
装的时候缺什么它自己会拉。
