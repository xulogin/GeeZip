# GeeZip

在 GEE 上先把数据压好，再下载。

下遥感数据最花时间的一步，是把几十个波段原样搬回本地。而很多人下回来第一件事就是降维——
真正占带宽的那一步白走了。

GeeZip 把顺序倒过来：**编码器放云上，解码器留本地。**

```
   云端（GEE）              带宽              本地
 ┌──────────────┐                      ┌──────────────┐
 │ 特征栈 D 维   │                      │              │
 │      ↓       │   只传这一份 ↓        │  解码器还原   │
 │  编码器前向    │ ───────────────→     │      ↓       │
 │      ↓       │   k 波段 uint8       │  D 维反射率   │
 │ tanh → uint8 │                      │              │
 └──────────────┘                      └──────────────┘
```
## 注意！！！

注意本项目是一个skill，并不能直接将我训练的模型直接用于压缩。他需要配合AI使用。最简单的用法如下：

   1. 你需要用codex 或者claude，直接安装该“skill” ，如输入：“安装https://github.com/xulogin/GeeZip ”
   2. 然后再结合skill提需求 ，如 “使用geeZip 下载xxx研究区的影像，xxx波段”。
   3. 然后它会根据你的需求，再结合我的工作流，完成对应的内容。
因为本项目是一个skill，并不是生产实际的压缩模型（例中测试也只是，一小块区域的，你换了区域肯定需要重新采样、训练、压缩、展平。但是不用担心，有了这套工作流程，AI都能全部自动完成）。


## 实测

| 场景 | 输入 | 下载量 | 压缩比 | 还原误差 |
|---|---|---|---|---|
| landsat年度 | 6 波段 | 4.97 MB → **1.19 MB** | **4.2 倍** | 0.0043，**低于传感器自身噪声** |
| landsat季度 | 6 波段 × 4 季 = 24 维 | 19.73 MB → **2.44 MB** | **8.1 倍** | 0.0091 |

昆明 22 公里见方，Landsat 8/9，2023 年，30 米。

Landsat 自己的辐射定标精度约 0.005 反射率——**年度那组的压缩损失比卫星
本身的测量误差还小。**

**波段越多越划算。** 相邻季节的影像长得像，越像越有得压。这恰好是大范围
时序数据最头疼的场景。

## 它是怎么工作的

**编码器和解码器是一起训的**，一个负责把 D 个数压成 k 个，一个负责还原回去。
训练时就按下载要用的精度（uint8）取整，所以部署的和训练的是同一个模型——
不这么做的话，精度会在下载那一步无声无息掉一截。

**只有编码器搬上 GEE。** GEE 能做前向传播（算一遍），做不了反向传播（学），
所以训练留在本地。解码本来就发生在下载之后，留本地天经地义。

**搬完自动核对两遍**，都对得上才让你下载：

| 核对 | 看什么 | 看不了什么 |
|---|---|---|
| 一致性 | 同一组输入，本地和 GEE 算出来一不一样 | 输入本身对不对 |
| 特征指纹 | 两边的特征栈算出来一不一样 | 模型权重对不对 |

缺一不可。特征栈在 `场景/<名字>.py` 和 `场景/<名字>.js` 里各写了一遍，
一旦两边漂了，第一道核对是抓不住的——脚本照样跑通、图照样出，数是错的。

实测两道分别对到 `1e-8` 和 `1e-11`。

```
场景/landsat年度.py   +   场景/landsat年度.js      ← 两边逐行对应
```

复制 `_新场景模板.py` / `.js`，改三处：特征栈、`FEATURES`、`sanity()`。
然后把 `配置.txt` 的 `scene` 改成新名字。

## 几句实话

- **它是有损的。** 名字里有 Zip，但别当成 WinRAR。还原出来不是逐位复制。
  实测误差小于传感器自身噪声，对绝大多数应用够用；要做逐位精确的存档，别用它。
- **换个地方可能要重训。** 单期影像的波段关系比较普适，换地方基本不掉；
  但季相物候是地域性的，跨气候区实测误差会翻一倍多。要跨区用，训练时
  就得把多个区域混进去。跑 `run.py 外推` 可以直接量出来。
- **它压的是波段之间的冗余**，不是图像空间上的冗余，和 JPEG 那类压缩不冲突。
- **小数据别用。** 就下一景几个波段，直接下更快。

## 一条踩出来的经验

**别用 `toArray` + `matrixMultiply` 去物化整幅栅格。**

逐点预测用它没问题，但整幅下载时会撞内存墙：

| | 全幅 743×743 @30m |
|---|---|
| 数组影像版 | `User memory limit exceeded` |
| **波段算术版** | **OK，1.19 MB，5 秒** |

MLP 的每个隐单元就是个加权和 `u_j = Σ W[j][i]·x_i + b_j`，用普通波段算术
表达即可。两版结果**逐位相同**（实测全幅最大差 = 0）。引擎里两版都在：
核对用数组版，下载用波段算术版，每次下载前自动对拍一次。

## 需要什么

Windows。Python 3.8+、Node.js 20.19+、Git，一个 GEE 账号和 Cloud Project，
以及能正常访问 GitHub 和 Earth Engine 的网络。

Python 包见 `requirements.txt`。**不需要 PyTorch 或 TensorFlow**——编码器和
解码器是 numpy 手写的，小到不值得上框架（通常几百到几千个参数）。
